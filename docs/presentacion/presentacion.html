El problema

Una temporada en el balneario, hoy

Cuadernos, planillas sueltas y llamados. Cuando llegan enero y febrero, el caos se multiplica.

📓

Reservas duplicadas

Dos familias con la misma carpa, las mismas fechas y un solo lugar en la arena.

🔍

“¿Qué carpa está libre?”

Responder una consulta simple implica revisar hoja por hoja y cruzar fechas a mano.

📉

Decidir a ciegas

Sin saber la ocupación real ni quiénes son los mejores clientes, no hay forma de planificar.

✅

CarpaGest centraliza carpas, clientes y fechas en un único sistema que valida cada operación antes de registrarla y responde al instante.

Módulo 1 · Carpas

Tu inventario, siempre ordenado

  • ➕
    Alta de carpas en segundos Número único, validado: no se pueden cargar duplicados ni valores inválidos.
  • 🗺️
    Mapeo simple, fiel a tu arena Cargás cada carpa con su sector y posición y el mapa se arma solo. Cada balneario tiene su propia U: el sistema se adapta.
  • 🛠️
    Mantenimiento sin borrar historial Activá o inactivá carpas (rotas, en reparación). Nunca se pierde información.
  • 📅
    Estado por fechas al instante Libre, reservada o alquilada para cualquier rango de días, calculado en tiempo real.

Bajo el capó

Arquitectura simple, sólida y lista para crecer

Toda la lógica está escrita en Python, organizada en tres capas bien separadas.

🖥️ InterfazMenú interactivo
Menú principal con submenús de Carpas, Reservas y Estadísticas. Cada dato que ingresa el usuario se pide hasta que sea válido: nunca llega un valor incorrecto a la lógica.
⚙️ Lógica de negocioFunciones puras
Más de 30 funciones con contrato documentado (pre y postcondiciones) y type hints. Validación de fechas, detección de superposiciones, búsquedas y ordenamiento propio. Cada función hace una sola cosa y avisa si algo falla.
🗂️ DatosEn memoria
Dos listas: carpas → [número, activa] y reservas → [carpa, dni, nombre, teléfono, desde, hasta, estado]. El estado de una carpa no se guarda: se calcula, así nunca queda desactualizado.
🐍 Python puro, sin dependencias 🔒 Borrado lógico (sin pérdida de datos) 📄 Docstrings con contratos 🚀 Etapa 2: persistencia en archivos 🗺️ Próximo: mapa configurable según la arquitectura de cada balneario
